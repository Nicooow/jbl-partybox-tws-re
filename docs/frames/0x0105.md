# 0x0105 — volume + playback-action sync

BESAUD command `0x0105` carries the **volume level** (u16) and a small **playback-action
code** (byte). It is both a "set my volume" notification and a transport hint: the receive
handler applies the volume locally through the standard volume pipeline and mirrors the
level into the shared context. Live testing previously showed action `0x01` = play and
`0x02` = volume; only the volume half is authoritative for this device's state.

* Firmware: `extracted/payload_1.bin` (BES2000IK), Thumb, load base `0x3C000000`. File offset = VA − `0x3C000000`.
* Shared context struct: `ctx = 0x2002F31C` (literal `0x3C01ACE0` = `0x2002F31C`).
* Frame envelope: `[type][cmd16 LE][payload…]`; `0x80`=command, `0x81`=ack. Generic sender `FUN_3c019fe0`, generic ack `FUN_3c01a08c`.
* Evidence status: **static reverse engineering** (volume setter previously live-injected OK).

## Wire format

### Outbound — speaker → peer (builder `FUN_3c01aca8(param_1, param_2)`)

18-byte buffer `[cmd16][payload]`; `FUN_3c019fe0` prefixes `0x80` → **19 bytes**.

| buf off | size | field | source |
|---|---|---|---|
| 0 | 2 | cmd16 (LE) `0x0105` | `movw r5,#0x105` |
| 2 | 2 | **volume (u16 LE)** | `param_1` (`strh r4,[sp,#6]`) |
| 4 | 4 | **action (u32 LE)** | `param_2` (`strb r1,[sp,#8]` after zeroing `[4..7]`) — only byte `[4]` is carried |
| 8 | 10 | padding | `0x00` × 10 |

Side effect on emit: `*(u16*)(ctx + 0x304) = param_1` (the local level is recorded before send).

### Inbound — peer → speaker (handler `parse_cmd` case `0x105` @ `0x3C01A2D6`)

| buf off | size | field | use |
|---|---|---|---|
| 0 | 2 | cmd16 `0x0105` | echoed into the ack buffer (`_auStack_2c = *(u32*)param_1`) |
| 2 | 1 | **volume** | `uVar6 = (u8)(*(u32*)param_1 >> 16)` = byte `[2]` |
| 3 | 1 | padding | — |
| 4 | 4 | **action (u32)** | `uStack_28 = *(u32*)(param_1+2)`; pass-through = `uStack_28 & 0xff` = byte `[4]` |
| 8 | 10 | echoed | copied into the ack buffer, otherwise unused |

Handler:

```c
case 0x105:
  uStack_28 = *(u32 *)(param_1 + 2);            /* action, bytes [4..7] */
  ...                                            /* copies bytes [8..17] into the ack buffer */
  uStack_2a._0_1_ = (u8)(*(u32 *)param_1 >> 16); /* volume = byte [2] */
  uVar6 = (u8)uStack_2a;
  FUN_3c020b70(uVar6, uStack_28 & 0xff);         /* volume setter, action = byte [4] */
  *(u16 *)(ctx + 0x304) = uStack_2a;             /* mirror level into ctx+0x304 */
  FUN_3c01a08c(auStack_2c, 0x12);                /* 18-byte 0x81 ack (echo) */
  return;
```

## `ctx+0x304` — the shared volume level

`ctx+0x304` is a **u16 volume/level slot** in the shared context. It is written on three paths:

| writer | value written |
|---|---|
| `FUN_3c01aca8` (outbound builder, event 2) | local `param_1` before sending |
| `FUN_3c020b70` (used by the inbound 0x0105 handler) | the volume being applied |
| 0x0101 and 0x0107 inbound handlers | `(short)` of the volume byte(s) they process |

So `ctx+0x304` is the device's current **synced volume level**; it is updated whether the
level arrived over BESAUD or was set locally.

## Volume setter chain

**`FUN_3c020b70(ushort param_1, param_2)`** (file `0x20B70`) — the BESAUD-facing setter. Its
decompiled form inlines the clamp, but the disassembly shows a **tail call**:

```
0x3C020B70  push {r4,r5,r6,lr}
            r4 = param_1 ; r6 = param_2 ; r0 = 3
            bl 0x3c01ca78            ; is state == 3 ?
            cbz r0 -> +0x3C020B7E
              r0 = func_3c01ca6c()   ; pointer to the active audio subsystem slot
              *r0 = (u8)param_1
              bl 0x3c016428          ; commit into that subsystem
       0x3C020B7E:
            r5 = (u8)r4
            strh param_1, [ctx+0x304]     ; record level
            r0 = sxtb(r5)                 ; clamped input = sign-extended low byte
            r1 = r6                       ; action
            b.w 0x3C01C8E8                ; TAIL CALL to the real applier
```

**`0x3C01C8E8(value, action)`** (the "downstream" core, no `.c` file) — disassembled:

```
cmp r0,#0x1f ; bgt -> r0 = 0x20          ; clamp high  → 32
cmp r0,#0   ; bgt -> keep (uxtb)         ; keep 1..0x1f
              else r0 = 0                ; clamp low   → 0
strb r4,[0x2002A848]                     ; store clamped level to global 0x2002A848
bl   0x3C042154                          ; notify (level)
bl   0x3C046384                          ; SVC: apply (level=r0/r4, 0, action=r1)
return 0
```

### Ranges / limits

* Volume is **clamped to `0 .. 0x20` (0…32)**. Values `1..0x1F` pass through, `≤0 → 0`,
  `≥0x20 → 0x20`. The clamp is applied twice (once in `FUN_3c020b70`'s byte, once in the
  `0x3C01C8E8` core), so an out-of-range level is saturated, never wrapped.
* The frame's volume field is a `u16`, but the pipeline consumes only its **low byte**
  (`sxtb`/`uxtb`), so effective volume is 0…32.
* The `action` byte selects a sub-command of the apply SVC (`func_0x3c046384(level, 0, action)`);
  observed `0x01` = play, `0x02` = volume.

### Sub-helpers referenced

| helper | VA | role |
|---|---|---|
| `func_0x3c01ca78` | `0x3C01CA78` | `return *(u8*)0x2002A82C == arg` (state predicate). Called with `3` → "audio/volume subsystem active". |
| `func_0x3c01ca6c` | `0x3C01CA6C` | returns a pointer to the active subsystem's volume byte slot |
| `func_0x3c016428` | `0x3C016428` | commit/notify into that subsystem |
| `FUN_3c042154` | `0x3C042154` | notification hook (level) |
| `func_0x3c046384` | `0x3C046384` | SVC applier `(level, 0, action)` |

## Call chain

| function | file | role |
|---|---|---|
| `FUN_3c012e84` | `0x12E84` | app event loop, `case 2` → `FUN_3c01aca8(*(i16*)(msg+4), *(u8*)(msg+6))` |
| `FUN_3c01aca8` | `0x1ACA8` | builds `[0105][vol][action][00×10]`; stores `ctx+0x304` |
| `FUN_3c019fe0` | `0x19FE0` | generic sender (session `ctx+0x310`) |
| `FUN_3c01a1f4` | `0x1A1F4` | `parse_cmd`; case `0x105` @ `0x3C01A2D6` |
| `FUN_3c020b70` | `0x20B70` | volume setter, stores `ctx+0x304`, tail-calls core |
| `0x3C01C8E8` | `0x1C8E8` | volume applier: clamp 0…32, store `0x2002A848`, notify, SVC apply |
| `FUN_3c01a08c` | `0x1A08C` | 18-byte `0x81` ack (echoes the frame) |

## Confidence & unknowns

**Confident:**
* Outbound `80 05 01 | <vol u16 LE> | <action u32, low byte used> | 00×10`; inbound reads
  `vol = byte[2]` and `action = byte[4]`, echoes the frame in its ack.
* `ctx+0x304` = current synced volume (u16), written by both TX and RX paths.
* Volume clamps to `0…0x20`; `FUN_3c020b70` **tail-calls** `0x3C01C8E8`, which stores the
  clamped level to `0x2002A848` and applies it via `FUN_3c042154` + `func_0x3c046384(level,0,action)`.

**Inferred:**
* `action` is an auxiliary sub-command of the apply SVC; live notes (`0x01`=play,
  `0x02`=volume) are consistent but not re-verified here.

**Unknown:**
* Exact semantics of the `action` values other than 1/2.
* `0x2002A82C` (state byte) and `0x2002A848` (clamped level) writers/readers beyond this path.
* The precise nature of `0x3C01C8E8`'s SVC `FUN_3c046384` (a jump into the audio subsystem).
