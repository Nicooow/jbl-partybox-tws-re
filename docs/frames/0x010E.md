# 0x010E — SOURCE selection sync (relay to the main SoC)

BESAUD command `0x010E` carries a **single source-id byte**. It is one half of the documented
BESAUD→main-SoC bridge: the builder emits the frame to the TWS peer **and** prints
`"\r\nSOURCE=%d\r\n"` to the internal UART that talks to the Sunplus SPHE8107 application SoC
(`FUN_3c041b2c`); the inbound handler latches the received byte into RAM `0x2004536C` and
prints the same `SOURCE=%d` line. Both directions therefore drive the main SoC's source input
selection.

* Firmware: `extracted/payload_1.bin` (BES2000IK), Thumb, load base `0x3C000000`. File offset = VA − `0x3C000000`. Same bytes aliased at `0x0C000000` (Δ `0x30000000`).
* Shared context struct: `ctx = 0x2002F31C` (literal `1cf30220` at `0x3C01A508`).
* Frame envelope: `[type][cmd16 LE][payload…]`; `0x80`=command, `0x81`=ack. Builder length fixed at `0x12` (18).
* Evidence status: **static reverse engineering only**. Addresses are VA unless "file 0x" is stated.

## Wire format

### Outbound — speaker → peer (builder `FUN_3c01ae68`)

18-byte local buffer, `0x80` type byte prefixed by `FUN_3c019fe0`. Total = **19 bytes**.

| offset | size | field | value / semantics |
|---|---|---|---|
| 0 | 1 | type | `0x80` |
| 1 | 2 | cmd16 (LE) | `0E 01` = `0x010E` |
| 3 | 1 | source id | `(byte)param_1` — the selected source |
| 4 | 15 | padding | `0x00` |

The buffer is `_uStack_1c = CONCAT22((u16)(byte)param_1, 0x10E)`, i.e. bytes
`[0E 01][source][00]`; `uStack_18/14/10/c = 0` cover the trailing 15 zero bytes.

**Side effect before send:** the builder calls `FUN_3c041b2c(_DAT_3c01aea0, param_1)`. The
literal `_DAT_3c01aea0` (VA `0x3C01AEA0`) resolves to string pointer **`0x3C050964`**, whose
contents are exactly `"\r\nSOURCE=%d\r\n"` (confirmed by raw dump). So it prints the SOURCE
line locally *and then* sends the frame.

### Inbound — peer → speaker (handler `parse_cmd` case `0x010E` @ `0x3C01A4A2`)

| offset | size | field | value / semantics |
|---|---|---|---|
| 0 | 1 | type | `0x80` |
| 1 | 2 | cmd16 (LE) | `0E 01` = `0x010E` |
| 3 | 1 | source id | `(char)param_1[1]` → stored to RAM `0x2004536C`, then printed |
| 4 | 15 | padding | ignored |

Handler body (`0x3C01A4A2`):

```c
case 0x10e:
  *puRam3c01a53c = (char)param_1[1];   /* RAM 0x2004536C = source id   */
  FUN_3c041b2c(uVar12);                /* uVar12 = 0x3C050964 = "\r\nSOURCE=%d\r\n" */
  break;                               /* → generic 0x81 ack           */
```

**Reply.** Falls through to the shared ack tail `LAB_3c01a26e` → `FUN_3c01a08c` (type `0x81`,
2-byte cmd16 echo `0x010E` + 16 bytes).

## Format strings / relay mechanism

* Inbound format string: **`0x3C050964` = `"\r\nSOURCE=%d\r\n"`** (the value of literal
  `uRam3c01a540`, and also the literal `_DAT_3c01aea0` used by the builder).
* `FUN_3c041b2c` (file `0x41B2C`) is the printf-style writer onto the internal UART toward the
  SPHE8107 main SoC. Per the project's decoded control-API string set
  (`DEMO= GAIN= LR= BYPASS= STANDBY= MUTE= AMP= SLEEP= I2SIN= BASS= PWR= PAIR= TWS= VSN= SOURCE= …`),
  a `SOURCE=%d` line is a **control/notification command for the main SoC**, not merely a debug
  print. So this frame's purpose is to make the main SoC switch its audio-source input.
* Direction detail: the **builder prints locally** (the local SoC also changes source) and
  **also frames** the value to the peer; the **inbound handler prints** the peer's value so the
  local SoC follows the peer's selection.

## Valid source ids

No enumeration or range check exists in either named file: the builder takes `(byte)param_1`
verbatim and the handler stores `(char)param_1[1]` verbatim. The source id is therefore an
arbitrary 8-bit value; any semantic mapping between value and physical input lives on the main
SoC side, not in `payload_1`.

## RAM `0x2004536C`

Written by `case 0x010E` (literal `0x3C01A53C` = `0x2004536C`). Within the reviewed files
(`parse_cmd` `0x3C01A1F4`, event loop `0x3C012E84`, builders `0x3C01AE68`/`0x3C01AEA4`, and
`0x3C01E954`/`0x3C0421F0`) there is **no reader** of `0x2004536C`. It is the local latch of
the source id last agreed with the peer; its consumers are outside the named files.

## Call chain

Emitted side:

| function | file | role |
|---|---|---|
| `FUN_3c012e84` | `0x12E84` | app event loop (`ctx+0x31C`); `case 0x18` (event `0x18`) → `FUN_3c01ae68` |
| `FUN_3c01ae68` | `0x1AE68` | `FUN_3c041b2c("\r\nSOURCE=%d\r\n", src)` then sender |
| `FUN_3c041b2c` | `0x41B2C` | printf-style internal-UART writer to the main SoC |
| `FUN_3c019fe0` | `0x19FE0` | generic BESAUD sender (`ctx+0x310` gate) |

Received side:

| function | file | role |
|---|---|---|
| `FUN_3c01a1f4` | `0x1A1F4` | `parse_cmd`; `TBH` base `0x3C01A20E`; `0x010E` → `0x3C01A4A2` |
| `FUN_3c041b2c` | `0x41B2C` | prints `"\r\nSOURCE=%d\r\n"` with the received byte |
| `FUN_3c01a08c` | `0x1A08C` | generic `0x81` ack sender |

## Confidence & unknowns

**Confident (direct code + constant evidence):**
* Outbound frame = `80 0E 01 | src | 00×15` (19 bytes); inbound reads one byte at payload+2.
* Both the builder and the inbound handler print the **same** string `0x3C050964` =
  `"\r\nSOURCE=%d\r\n"` via `FUN_3c041b2c`; the builder's `_DAT_3c01aea0` == `0x3C050964`.
* Inbound stores the byte to RAM `0x2004536C`.
* No source-id validation in `payload_1`.

**Inferred (labelled as such):**
* The printed `SOURCE=%d` line is a *control command* to the SPHE8107 main SoC (based on the
  decoded control-string set of `FUN_3c041b2c`), not just diagnostics.

**Unknown / not verified:**
* Readers/consumers of RAM `0x2004536C` (outside the named files).
* Poster of app event `0x18`.
* The value↔source mapping (handled on the main SoC).
* Ack body beyond the 2-byte cmd16 echo (generic tail leaves 16 bytes uninitialised).
