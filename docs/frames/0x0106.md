# 0x0106 — link/stream state sync

BESAUD command `0x0106` is a small **state-sync / "ready" handshake**. It carries two bytes
(a mode byte and a marker byte) and is symmetric in shape but strongly **asymmetric in
effect**: whichever side is in link state `ctx+9 == 1` re-drives its local BT transport
state, while the other side only acknowledges and records the mode. Locally observed bytes
are `02 00 00 ff` (mode `2`, marker `0xff`).

* Firmware: `extracted/payload_1.bin` (BES2000IK), Thumb, load base `0x3C000000`. File offset = VA − `0x3C000000`.
* Shared context struct: `ctx = 0x2002F31C`.
* Frame envelope: `[type][cmd16 LE][payload…]`; `0x80`=command, `0x81`=ack.
* Evidence status: **static reverse engineering only**.

## Wire format

### Outbound — speaker → peer (builder `FUN_3c01ace4(param_1, param_2)`)

`FUN_3c019fe0` prefixes `0x80` → **19 bytes**.

| buf off | size | field | source (disasm) |
|---|---|---|---|
| 0 | 2 | cmd16 (LE) `0x0106` | `strh r4,[sp,#4]`, `r4=0x106` |
| 2 | 1 | **mode byte** | `strb r0,[sp,#6]` = `param_1` |
| 3 | 1 | 0 | zeroed (`str r3,[sp,#4]`) |
| 4 | 4 | 0 | zeroed (`str r3,[sp,#8]`) |
| 5 | 1 | **marker byte** | `strb r1,[sp,#9]` = `param_2` |
| 6 | 12 | 0 | zeroed (`sp+0xA..0x16`) |

So the payload is exactly `{ [2]=param_1, [5]=param_2 }`. On the wire the observed pattern
`02 00 00 ff` = `param_1=2`, `param_2=0xff`.

### Inbound — peer → speaker (handler `parse_cmd` case `0x106` @ `0x3C01A306`)

```c

  uVar12 = *(u32*)(param_1 + 5);          /* bytes [10..13] (zero here) */
  uVar5  = param_1[1];                    /* bytes [2..3] */
  *(u8*)(ctx + 0x16) = uVar6;             /* record marker byte */
  uVar6 = FUN_3c01a124((char)uVar5, uVar6, uVar12);   /* arbitration → ack byte [2] */
```

The **ack context manager** `FUN_3c01a08c` is called *before* the local-action branch, so an
inbound `0x0106` always produces the standard 18-byte reply whose byte `[2]` is the
arbitration code from `FUN_3c01a124`.

## The `ctx+9` states — meaning and asymmetry

`ctx+9` is a **link/role state byte** (a sibling of `ctx+8`; event-6 teardown `FUN_3c01abc8`
copies `ctx+9 = ctx+8`). The handler branches on it:

| `ctx+9` | meaning (model) | behaviour here |
|---|---|---|
| `1` | initiator / master | performs the **full local resync**: `FUN_3c040ff4(6)`, then re-posts a transport event via `FUN_3c01322c(...)` and `FUN_3c01dc64(1)` |
| `2` | follower / obedientside | **no resync** — only `FUN_3c040ff4(6)` then return (still acks) |
| other (`0`, `3`, `4`) | neither / transitional | same as `2`: no resync |

The asymmetry is proven by code: only `ctx+9 == 1` reaches the `FUN_3c019600` / role / `FUN_3c01322c`
block. `FUN_3c01a124` may itself **set `ctx+9 = 4`** on an incompatible configuration, pushing
the device into the "other" state.

Note the role test inside the `ctx+9==1` block uses `func_0x3c01d3ac() != 0x10` (and `== 0x10`),
i.e. role `0x10` selects a different argument order for `FUN_3c01322c` — the same role
discriminator (`*(u8*)(0x200351EC+5)`) used by the 0x0104 handler.

## `FUN_3c01a124` — arbitration / compatibility gate (file `0x1A124`)

Signature `FUN_3c01a124(int param_1, int param_2, uint param_3)`. Called with
`param_1 = (char)byte[2]` (mode), `param_2 = byte[5]` (marker), `param_3 = u32@[10..13]`.

Returns a small code that is placed into **ack byte `[2]`**:

| return | condition | side effects |
|---|---|---|
| `1` | role-compatible / nothing to do (early paths, incl. `param_1==1` stream already OK) | `FUN_3c014310(1,0,c)`, `FUN_3c040ff4(7)`, `FUN_3c0457f4(*(ctx+0x2d4),3000)` |
| `2` | `param_1 == 1` and the stream object is invalid/not `+0x22==3`, or `param_2 == 0xff` | `FUN_3c014310(2,0,0xff)`, `FUN_3c040ff4(7)`, `FUN_3c0457f4(ctx+0x2d4,3000)`, close `*(u32*)0x20032C88` |
| `4` | `param_1 != 1` and `*(u32*)0x2002ABE0 ∉ {0,1}` | **`*(u8*)(ctx+9) = 4`**, close `*(u32*)0x20032C88` |

Key checks inside: `iVar4 = *(int*)(ctx + 0x28c)` (the active **stream/session object**);
`*(char*)(iVar4 + 0x22) == 3` means "stream active". `func_0x3c043958()` reads `*(u32*)0x2002ABE0`
(a capability/role global). So `FUN_3c01a124` decides whether the peer's announced
mode/marker are **consistent with the current stream state** and returns the verdict.

## What the frame synchronises

`0x0106` synchronises the **link stream mode/marker**:
* Byte `[2]` (mode) and byte `[5]` (marker, mirrored into `ctx+0x16`) — the peer's stream
  state descriptor; `0x0101` also reads/uses `ctx+0x16`.
* The *effect* of the frame is one-sided: the `ctx+9==1` device uses it as a trigger to
  re-launch local BT transport (`FUN_3c01322c` posts app-event `1`, `FUN_3c01dc64(1)`),
  whereas the `ctx+9==2` device only records the marker and acks.

## Confidence & unknowns

**Confident:**
* Outbound = `80 06 01 | mode@[2] | 00 00 | marker@[5] | 00×12`; inbound mirrors `byte[5]` into
  `ctx+0x16`, computes `FUN_3c01a124((char)byte[2], byte[5], u32@[10..13])` and puts the result
  in ack byte `[2]`.
* Only `ctx+9 == 1` re-drives local transport; `ctx+9 == 2`/other are no-ops besides the ack.
* `FUN_3c01a124` returns `1`/`2`/`4` and can set `ctx+9 = 4`; it consults the stream object
  `ctx+0x28c` (`+0x22==3` = active) and global `*(u32*)0x2002ABE0`.

**Inferred:**
* `ctx+9` is the link role/state (1 = master). `ctx+0x16` = the peer's last mode/marker byte.

**Unknown / not verified:**
* UI-level meaning of mode value `2` and marker `0xff`.
* `FUN_3c019600`, `FUN_3c01dc64`, `FUN_3c040ff4`, `FUN_3c013350`, `FUN_3c01322c` internals were
  not decompiled (identified only by their call sites and posted event ids).
* `0x2002ABE0` and `0x20032C88` writers were not located.
