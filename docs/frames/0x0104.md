# 0x0104 — transport / playback-action broadcast (play-pause & friends)

BESAUD command `0x0104` is the application-layer **transport-action broadcast**. A device
that changes its local playback state (play/pause, track skip …) sends this frame to the
peer so both sides stay in lock-step; the peer re-executes the *same* action locally. The
frame carries a single **u32 action code** (the only payload field) and is both the emit
side and the receive side of the same logical "who pressed play" event.

* Firmware: `extracted/payload_1.bin` (BES2000IK), Thumb, load base `0x3C000000`. File offset = VA − `0x3C000000`. Aliased at `0x0C000000` (Δ `0x30000000`).
* Shared context struct: `ctx = 0x2002F31C` (literal-pool verified: words at `0x3C013144`, `0x3C01A508`, `0x3C01ACE0`, `0x3C01AE24`, `0x3C0131D0` all = `0x2002F31C`).
* Frame envelope: `[type][cmd16 LE][payload…]`; `0x80`=command, `0x81`=ack. Generic sender `FUN_3c019fe0`, generic ack `FUN_3c01a08c`.
* Evidence status: **static reverse engineering only** (the injectable behaviour "action 0x06 = play/pause" was previously live-confirmed; see repo root).

## Wire format

### Outbound — speaker → peer (builder `FUN_3c01af7c`)

18-byte local buffer `[cmd16][payload]`, then `FUN_3c019fe0` prefixes type `0x80` → **19 bytes** on the wire.

| offset | size | field | value / semantics |
|---|---|---|---|
| 0 | 1 | type | `0x80` — written by `FUN_3c019fe0` |
| 1 | 2 | cmd16 (LE) | `04 01` = `0x0104` |
| 3 | 4 | **action (u32 LE)** | `param_1`, split as `[2..3]=(u16)param_1`, `[4..5]=(u16)(param_1>>16)` |
| 7 | 12 | padding | `0x00` × 12 (`uStack_16`, `uStack_14`, `uStack_10`, `uStack_c` all 0) |

Buffer-relative (0 = cmd16) the action occupies bytes `[2..5]`.

### Inbound — peer → speaker (handler `parse_cmd` case `0x104` @ `0x3C01A2CC`)

| offset | size | field | value / semantics |
|---|---|---|---|
| 0 | 1 | type | `0x80` (command path) |
| 1 | 2 | cmd16 (LE) | `04 01` = `0x0104` |
| 3 | 4 | **action (u32 LE)** | read as `*(u32*)(param_1 + 1)` = bytes `[2..5]`; forwarded verbatim to app-event `0x0F` |
| 7 | 12 | padding | ignored |

Handler body (2 instructions):

```c
case 0x104:
  FUN_3c013298(*(undefined4 *)(param_1 + 1));   /* posts app-event 0x0F with the u32 */
  break;                                         /* → generic 0x81 ack */
```

`FUN_3c013298(u32)` = `auStack_c[0]=u32; FUN_3c0131d8(0xF, auStack_c, 4)` — i.e. it posts app-event `0x0F`
carrying the 4-byte action. It is called **only** from this handler (single call site `0x3C01A2D0`).

## Emitted side

**Builder:** `FUN_3c01af7c(param_1)` (file `0x1AF7C`):

```c
uStack_16 = 0; uStack_1a = (u16)param_1; uStack_18 = (u16)(param_1 >> 0x10);
uStack_14 = 0; uStack_10 = 0; uStack_c = 0;
uStack_1c = 0x104;                 /* cmd16 = 0x0104 */
FUN_3c019fe0(&uStack_1c, 0x12, 1000);
```

The action `param_1` is the only non-constant field.

**Trigger (internal app-event `0x0E`).** App event loop `FUN_3c012e84` (file `0x12E84`), queue `ctx+0x31C`:

```c
case 0xe:
  FUN_3c01af7c(puVar5[1]);   /* puVar5[1] = the u32 action */
  break;
```

**Producer of event `0x0E` = `FUN_3c013280(param_1)`** (file `0x13280`):

```c
auStack_c[0] = param_1;
FUN_3c0131d8(0xe, auStack_c, 4);
```

`FUN_3c013280` is the *sole* poster of event `0x0E`. Its BL call sites (scanned from the image) are:

| call site (VA) | containing function | value posted | context |
|---|---|---|---|
| `0x3C019C78` | `FUN_3c019834` (profile/BT callback state machine) | `FUN_3c013280(6)` | local profile event |
| `0x3C043908` | `FUN_3c043854` (local playback/AVRCP event loop) | `FUN_3c013280(6)` | guarded by `role()==1` **and** `*(ctx+9)==1` |
| `0x3C042922` | `0x3C0429xx` routine | (variable) | upper BT-stack layer |

So the u32 an outbound `0x0104` carries is produced by the **local BT/A2DP transport state
machines** (not by any BESAUD code). Both identified local producers broadcast action `6`
(= play, per the live note "action 06 = PLAY"): the local side, when it is role `1` and
link state `1` and observes a play, emits `0x0104` action `6` to its peer.

`FUN_3c043854` is a wait-loop (`FUN_3c045984(…,-1)` blocks; `FUN_3c0456a4(1000)` waits
1000 ms) reading a state byte; when the byte is `-1` (0xFF) and `role()==1` and `ctx+9==1`
it calls `FUN_3c013280(6)`.

## Received side — the event-0x0F consumer

`FUN_3c012e84`, `case 0xf` dispatches on `puVar5[1]` (the u32 action) through a **5-entry
absolute jump table at `0x3C012F44`** (base rule: index = action − 5). Decoded legal codes:

| action | target | effect |
|---|---|---|
| 5 | `code_r0x0c012ee8` (`0x3C012EE8`) | local transport action |
| 6 | `0x3C012EE8` | local transport action (= PLAY) |
| 7 | loop tail | **no-op** (ignored) |
| 8 | `0x3C012EE8` | local transport action |
| 9 | `0x3C0130BC` … | `*(u8*)(ctx+0x15) = 1` (set the suppression flag) |

Codes **5, 6, 8 are synonyms** (identical handler). Code **7 is dropped**. Code **9 is a
one-shot flag set** — it raises `ctx+0x15`, which is exactly the guard the 5/6/8 handler
tests, so `9` *suppresses* subsequent transport actions.

### Handler `0x3C012EE8` (codes 5 / 6 / 8)

```c
iVar8 = func_0x3c01d3ac();          /* role() */
if (iVar8 != 1) goto tail;          /* only role 1 acts */
if (*(char *)(ctx + 0x15) != 0) goto tail;   /* suppressed / busy */
FUN_3c0141f8(1, 2, 0, &UNK_0c014f65);        /* inject transport event into BT stack */
iVar8 = func_0x3c043958();          /* *(u32*)0x2002ABE0 */
if (iVar8 == 1) func_0x3c0439ec();  /* re-sync: emit 0x0107 (event 4) */
tail:
  FUN_3c046154(*(u32*)(ctx + 0x31c), puVar5);   /* release the queue item */
```

**Callee roles**

| callee | VA / file | what it is |
|---|---|---|
| `func_0x3c01d3ac` | `0x3C01D3AC` | `ldr r3,[0x3C01D3B4=0x200351EC]; ldrb r0,[r3,#5]; bx lr` → **`role()` = `*(u8*)(0x200351EC + 5)`**. |
| `FUN_3c0141f8` | `0x3C0141F8` | transport-event injector: `store param_4→ctx+0x35c, param_3→ctx+0x358`, then `FUN_3c01d858(route=2, param_1=1, 0,0, param_3, cb)` (the internal BT msg queue) and `(*(code**)(ctx+0x360))(...)`. Here it injects the local play/pause state change. |
| `FUN_3c043958` | `0x3C043958` | `ldr r0,[0x3C043960=0x2002ABE0]; bx lr` → `return *(u32*)0x2002ABE0`, compared `== 1`. |
| `FUN_3c0439ec` | `0x3C0439EC` | builds a 5-field struct and posts app-event `4` via `FUN_3c013254` → runs the **0x0107** builder (`FUN_3c01ad94`); also sets `ctx+0x3b2 = 2`. |

### The pointer `&UNK_0c014f65` (= `0x3C014F65`)

This is **not data** — it is a **Thumb callback function pointer** (odd address; the code it
points to starts at `0x3C014F64`). It is passed as the 4th argument to `FUN_3c0141f8`, which
stores it at `ctx+0x35c` for later invocation. (The same pointer also appears in the event
loop's `case 9` literal pool as `uRam3c013148 = 0x0C014F65`.)

Body at `0x3C014F64` (disassembled):

```c
if (arg != 2) return/other;                     /* cmp r0,#2 / bne */
if (*(u8*)(g1) == 1) { *(u8*)(g1) = 0; return; }/* clear a pending flag */
if (FUN_3c01ac7c() == 0 && *(u8*)(g2) != 0) {   /* else branch */
      *(u32*)(ctx + 0x340) = 8;                  /* set state 8 */
      FUN_3c014ef4(); FUN_3c01369c(); FUN_3c017990();
      *(u8*)(ctx + 0x33d) = 0;
}
```

So it is the **track-advance / playlist-step handler**: it sets state `8` on `ctx+0x340`,
runs three helpers and clears a marker at `ctx+0x33d`.

### Conditions `role()==1` and `ctx+0x15==0`

* **`role()==1`** (`= *(u8*)(0x200351EC+5)`): `0x200351EC` is the device-role/state record;
  byte `+5` is the role discriminator. Only the **role-1 device** applies an inbound
  transport action locally. The same predicate gates the 0x0106 handler (`role()!=0x10`) and
  the 0x010D handler, and is compared against `0x10` (a second, distinct role) elsewhere.
  Working model: role `1` = the "primary/master" unit.
* **`ctx+0x15==0`**: a **suppression/busy flag**. Code `9` sets it to `1`; teardown paths
  (`0x0103` handler via `FUN_3c014114`, event-6 handler `FUN_3c01abc8`) clear it to `0`.
  While it is `1`, transport actions (codes 5/6/8) are ignored.

## Confidence & unknowns

**Confident (code + constants):**
* Outbound frame = `80 04 01 | <u32 action LE> | 00×12` (19 bytes); inbound reads the same
  u32 at bytes `[2..5]` and forwards it verbatim to app-event `0x0F`.
* `FUN_3c013280` is the sole producer of event `0x0E`; local producers post action `6`.
* Event `0x0F` codes: **5/6/8 → same handler**, **7 → ignored**, **9 → `ctx+0x15 = 1`** (via
  a 5-entry absolute table at `0x3C012F44`).
* The 5/6/8 handler fires only when **`role()==1` and `ctx+0x15==0`**, then injects a BT
  transport event (`FUN_3c0141f8(1,2,0,cb)`) and, if `*(u32*)0x2002ABE0==1`, re-emits `0x0107`.
* `&UNK_0c014f65` = Thumb callback pointer to code at `0x3C014F64` (track-advance helper).

**Inferred (labelled):**
* Action codes are a **transport action space** shared by both directions: `6` = play/pause
  (live-confirmed); `5`,`8` behave identically to `6` in this firmware; `7` is defined but
  ignored; `9` = "suppress transport actions".
* `role()==1` = primary/master; `0x10` = an other role. `ctx+0x15` = busy/teardown suppression flag.

**Unknown / not verified:**
* Exact meaning of actions `5`, `7`, `8`, `9` at the UI level (only `6` is live-confirmed).
* The `0x3C042922` producer's posted value (its containing function was not decompiled).
* `0x200351EC` (role record) and `0x2002ABE0` writers were not located.
* The ack body for `0x104` is not emitted by the handler (only the generic cmd16 echo path is
  reachable), so the ack's remaining bytes are uninitialised stack on this path.
