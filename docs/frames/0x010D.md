# 0x010D — TWS engine reset / abort notification

BESAUD command `0x010D` is a **"reset/abort the TWS link" notification**. The sender first flushes
its *own* TWS engine (state machine, timers, audio buffers) with `FUN_3c01369c()`, then tells the
peer with a **fire-and-forget** `0x010D` (timeout `0`, so no ack is expected). The receiver acts
on it only when it is in the committed role-1 link state (`ctx+9 == 1`): depending on its own link
role it either starts a full local teardown by emitting `0x0103`, or sets the handoff flag and runs
the disconnect callbacks. It carries **no data**.

* Firmware: `extracted/payload_1.bin` (BES2000IK), Thumb, load base `0x3C000000`. File offset = VA − `0x3C000000`. Aliased at `0x0C000000` (Δ `0x30000000`).
* `ctx = 0x2002F31C` (literal `iRam3c01a508` / `iVar8` in `parse_cmd`).
* Envelope: `[type][cmd16 LE][payload…]`, type `0x80`=command / `0x81`=ack.
* Evidence status: **static RE only.**

## Wire format

### Outbound — speaker → peer (builder `FUN_3c01b008`, file `0x1B008`)

```c
uStack_24 = 0x10d;  uStack_20 = 0;  uStack_1c = 0;  uStack_18 = 0;  uStack_14 = 0;
FUN_3c01369c();                       /* flush the LOCAL TWS engine first */
FUN_3c019fe0(&uStack_24, 0x12, 0);    /* cmd 0x010D, 18-byte body, timeout = 0 */
```

Constant frame, no state sampled. Wire = **19 bytes**:

| off | size | field | value |
|---|---|---|---|
| 0 | 1 | type | `0x80` (added by `FUN_3c019fe0`) |
| 1 | 2 | cmd16 (LE) | `0D 01` = `0x010D` |
| 3 | 16 | payload | `0x00` ×16 |

**Why timeout 0.** `FUN_3c019fe0(buf, len, timeout)` only arms the ack wait when
`timeout != 0`: it then sets `ctx+0x315 = 1` and waits via `FUN_3c045bcc(session, …)`. With
`timeout = 0` it sends and returns immediately — the correct choice for a reset/abort that
must not block on a peer which is itself tearing down (and which the local side has already
forgotten). The send is still session-gated (`*(u32*)(ctx+0x310) != 0`).

### Inbound — peer → speaker (handler `parse_cmd` case @ `0x3C01A47E`)

```c
case 0x10d:
  if (*(char*)(ctx + 9) != 1) return;           /* only the committed role-1 link reacts */
  iVar7 = func_0x3c01d3ac();                     /* current link role */
  if (iVar7 != 1 && (iVar7 = func_0x3c01d3ac(), iVar7 != 0x10)) {
      FUN_3c014158();                            /* role ∉ {1,0x10} → emit 0x0103 teardown */
      return;
  }
  *(char*)(ctx + 0x12) = 1;                       /* handoff / role-switch pending */
  FUN_3c0146f8();                                 /* set ctx+0x11=1, run vtable callbacks */
  return;                                         /* no ack emitted */
```

No payload field is read, and the handler returns (no generic `0x81` ack).

## The state gate (`ctx+9`, roles `1` / `0x10`)

* **`ctx+9 == 1` is mandatory.** `ctx+9` is the *committed link role* (set by the full-teardown
  handler `FUN_3c01abc8` as `ctx+9 = ctx+8`; `ctx+8` ∈ {1,2} is the live role, {3,4} post-teardown).
  If `ctx+9 != 1`, an inbound `0x010D` is a complete no-op.
* **Role = `func_0x3c01d3ac()`** (getter for the runtime link role; observed values in the image
  are `1`, `8`, `0x10`). The handler routes on it:
  * role ∈ {`1`, `0x10`} → `ctx+0x12 = 1` and `FUN_3c0146f8()` (the two "keep the link object,
    just mark teardown/handoff" roles);
  * any other role → `FUN_3c014158()`, i.e. fall back to the full `0x0103` teardown path.
* **`ctx+0x12`** is the *role-switch/handoff pending* flag: set here for roles 1/0x10, cleared by
  the event-loop `case 3`/`case 4` when `func_0x3c01ac7c()==0` (which then also calls
  `FUN_3c0146f8`). The event-loop `case 0x0D` sets it for role `0x10`.

## Helper functions

| function | file | role |
|---|---|---|
| `FUN_3c01369c()` | `0x1369C` | **flush/reset the local TWS engine.** Sets the busy flag `ctx+0x22 = 1`; if `ctx+8 == 1` calls `(ctx+0x15c)(ctx+0xfc)`; calls `(ctx+0x1f0)(arg)`; pauses two engine timers (`FUN_3c045a94(ctx+0x24/0x38, -1)`); toggles `ctx+0x10 = 1/0` around three `FUN_3c013474(global)` flushes; `func_0x3c017990()`; zeroes `ctx+0x2a8`, `ctx+0x2ac` and four global slots; stops the two timers (`FUN_3c045aac`); clears `ctx+0x22 = 0`; ends with an indirect tail call. In short: stop timers, flush audio buffers, clear counters/flags. |
| `FUN_3c014158()` | `0x14158` | posts **app event `0x0A`** (8-byte zero message). `FUN_3c012e84` `case 0x0A` → `FUN_3c01af50` → emits `0x0103` (the full teardown message). See `0x0103.md`. |
| `FUN_3c0146f8()` | `0x146F8` | `(**(ctx+0x3a8))(ctx); ctx+0x11 = 1; (**(ctx+0x3ac))(ctx);` — runs the two context-vtable callbacks and sets the teardown-in-progress flag `ctx+0x11`. Same callbacks `FUN_3c014114(1)` (used by 0x0103) invokes, but without the `ctx+0x340 = 7` step and without posting event 9. |
| `FUN_3c019fe0` | `0x19FE0` | `0x80` sender; timeout-0 → no ack wait. |

**`ctx+0x11`** = teardown-in-progress (set here, in 0x0103 via `FUN_3c014114(1)`, in 0x0109, and by
the event-6 handler). **`ctx+0x12`** = handoff/role-switch pending. **`ctx+9`** = committed role.

## Reference / who calls the builder

`FUN_3c01b008` has **no `BL` caller** in the image; the bounded pointer scan found four data
references (all the pool word `0x0C01B009`):

| stored at (VA) | neighbouring pool words |
|---|---|
| `0x3C002164` | pool word inside a function (data, not executable code) |
| `0x3C013958` | `0x2002F31C` (ctx), `0x0C01369D` (= `&FUN_3c01369c`), then `&FUN_3c01b008` |
| `0x3C0144E4` | `0x2002F31C`, `0x2002D2F0`, `0x2002F314`, `0x0C013741`, `0x0C014FD1`, then `&FUN_3c01b008` |
| `0x3C0151E8` | `0x2002F31C`, `0x2002D2F4`, `0x2002A6B2`, `0x0C01369D` (=`&FUN_3c01369c`), `0x0C0457F5`, then `&FUN_3c01b008`, `0x20030DEC` |

Every table that contains the send routine also contains the context pointer `0x2002F31C` and the
reset routine `&FUN_3c01369c` (`0x0C01369D`). That is consistent with `FUN_3c01b008` being an
**indirectly-invoked descriptor routine** `{ctx, reset = FUN_3c01369c, send = FUN_3c01b008, …}`
called by the TWS state machine (there is no static call edge, exactly as for the 0x010C builder).
The reset+notify pairing is baked into `FUN_3c01b008` itself (`FUN_3c01369c()` then send), so any
caller that reaches it performs "flush engine, then tell the peer".

## Confidence & unknowns

**Confident:**
* Outbound is `80 0D 01 | 00×16`, sent with timeout `0` (fire-and-forget) after `FUN_3c01369c()`.
* Inbound is a no-op unless `*(u8*)(ctx+9) == 1`; then role `= func_0x3c01d3ac()`: role ∈ {1,0x10}
  → `ctx+0x12 = 1` + `FUN_3c0146f8()`, else → `FUN_3c014158()` (emit `0x0103`). No ack is sent.
* `FUN_3c014158` → event `0x0A` → `FUN_3c01af50` → `0x0103`; `FUN_3c0146f8` → `ctx+0x11 = 1` + the
  same two vtable callbacks used by `FUN_3c014114`.
* Pointer scan: `FUN_3c01b008` appears only as the pool word `0x0C01B009` at `0x3C002164`,
  `0x3C013958`, `0x3C0144E4`, `0x3C0151E8` — no `BL` caller.

**Inferred (labelled):**
* `0x010D` = "reset/abort the TWS link": reset locally, notify the peer best-effort. Roles `1` and
  `0x10` keep the link object and only mark teardown/handoff (`ctx+0x12 = 1`), whereas the other
  roles escalate to the full `0x0103` teardown. This makes `0x010D` the "soft" reset counterpart of
  `0x0103`/`0x0109`.
* `ctx+0x12` = handoff/role-switch pending; `ctx+0x11` = teardown-in-progress.

**Unknown / not verified:**
* No static caller for `FUN_3c01b008`; the exact descriptor-table owner (four pool tables listed
  above) and the runtime condition that triggers a `0x010D` are not resolved.
* `FUN_3c01369c`'s vtable targets (`ctx+0x15c`, `ctx+0x1f0`, the three `FUN_3c013474` globals) and
  the final indirect jump (`_DAT_3c04c674`) were not resolved to concrete functions.
* The meaning of role value `8` (present in `func_0x3c01d3ac()` consumers elsewhere) is not settled.
