# 0x010F — STANDBY (power-state) sync / relay to the main SoC

BESAUD command `0x010F` carries a **single 0/1 byte** that drives standby. On receive it
latches a flag at RAM `0x20040F9D` and then emits `"\r\nSTANDBY=%d\r\n"` toward the main
SPHE8107 SoC through `FUN_3c0421F0`. It is the second half of the documented BESAUD→main-SoC
bridge (the first being `0x010E`/`SOURCE=%d`). Unlike `0x010E`, the outbound builder does **not**
print locally: `FUN_3c01aea4` only frames the value to the peer.

* Firmware: `extracted/payload_1.bin` (BES2000IK), Thumb, load base `0x3C000000`. File offset = VA − `0x3C000000`. Same bytes aliased at `0x0C000000` (Δ `0x30000000`).
* Shared context struct: `ctx = 0x2002F31C` (literal `1cf30220` at `0x3C01A508`).
* Frame envelope: `[type][cmd16 LE][payload…]`; `0x80`=command, `0x81`=ack. Builder length fixed at `0x12` (18).
* Evidence status: **static reverse engineering only**. Addresses are VA unless "file 0x" is stated.

## Wire format

### Outbound — speaker → peer (builder `FUN_3c01aea4`)

18-byte local buffer, `0x80` type byte prefixed by `FUN_3c019fe0`. Total = **19 bytes**.

| offset | size | field | value / semantics |
|---|---|---|---|
| 0 | 1 | type | `0x80` |
| 1 | 2 | cmd16 (LE) | `0F 01` = `0x010F` |
| 3 | 1 | state | `(u16)param_1` — `0` or `1` (standby off / on) |
| 4 | 15 | padding | `0x00` |

Buffer is `_uStack_1c = CONCAT22((u16)param_1, 0x10F)` → bytes `[0F 01][state][00]`;
`uStack_18/14/10/c = 0` fill the trailing 15 bytes. No local print call in this builder.

### Inbound — peer → speaker (handler `parse_cmd` case `0x010F` @ `0x3C01A4B0`)

| offset | size | field | value / semantics |
|---|---|---|---|
| 0 | 1 | type | `0x80` |
| 1 | 2 | cmd16 (LE) | `0F 01` = `0x010F` |
| 3 | 1 | state | `param_1[1]`; **only `0` and `1` are acted upon** |
| 4 | 15 | padding | ignored |

Handler body (`0x3C01A4B0`):

```c
case 0x10f:
  uVar4 = param_1[1];              /* byte at payload+2   */
  *puRam3c01a544 = 1;             /* RAM 0x20040F9D = 1  */
  if ((char)uVar4 == '\x01' || (char)uVar4 == '\0')
      FUN_3c0421F0();             /* → prints "\r\nSTANDBY=%d\r\n" */
  break;                          /* → generic 0x81 ack  */
```

So: unconditionally latch `RAM[0x20040F9D] = 1`, then for a valid state value (`0` or `1`)
invoke `FUN_3c0421F0`. Values other than `0`/`1` still set the latch but do not print.

**Reply.** Falls through to `LAB_3c01a26e` → `FUN_3c01a08c` (type `0x81`, 2-byte cmd16 echo
`0x010F` + 16 bytes).

## Meaning of the 0/1 value

`0` / `1` = the standby (power-down / power-up) state. Both accepted values call the same
printer, so the byte is a **state level**, not an action verb. Which numeric value means
"enter standby" vs "leave standby" is **inferred** from the `STANDBY=%d` semantics and is not
proven by these files (the same printer is reached for both values).

## RAM `0x20040F9D`

Set to `1` by `case 0x010F` (literal `0x3C01A544` = `0x20040F9D`). Within the reviewed files
(`parse_cmd` `0x3C01A1F4`, event loop `0x3C012E84`, builders `0x3C01AE68`/`0x3C01AEA4`,
`0x3C01E954`, `0x3C0421F0`) there is **no reader** of `0x20040F9D`. The address sits in the BT
runtime state block `0x20040Fxx` — the same region as the audio-stream gate byte `0x20040F85`
noted in the project AGENTS (they are different bytes, Δ `0x18`) — so it is plausibly a
"standby engaged / activity" latch in that block, but its consumers are outside the named
files. Semantics = **inferred**.

## `FUN_3c0421F0` and the standby sequence

`FUN_3c0421F0(int param_1)` (file `0x421F0`) is the **standby notifier** — a buffered
`printf`-to-UART path distinct from `0x010E`'s `FUN_3c041b2c`:

```c
void FUN_3c0421F0(int param_1) {
  if (param_1 == 0) func_0x3c0464b8();               /* some flush/reset when arg == 0 */
  uStack_10 = _DAT_3c042208; iStack_c = param_1;
  n = FUN_3c04a940(auStack_98, 0x80, _DAT_3c042208); /* format into 0x80-byte buffer   */
  if (n < 0x7e) auStack_98[n++] = 0x0d;              /* append CR */
  if (n < 0x7f) auStack_98[n++] = 0x0a;              /* append LF */
  if (n != 0) FUN_3c04196c(auStack_98);              /* emit the line */
}
```

The format string `_DAT_3c042208` (VA `0x3C042208`) resolves to **`0x3C2F0F70`** whose contents
are exactly **`"\r\nSTANDBY=%d\r\n"`** (confirmed by raw dump). `FUN_3c04196c` is the string
emitter on the internal UART/console channel toward the main SoC.

**Standby/power-down sequence (as visible statically):**

1. Peer sends `0x010F` with state `0` or `1`.
2. `parse_cmd` case `0x010F` sets `RAM[0x20040F9D] = 1`.
3. For valid states it calls `FUN_3c0421F0`, which (if its argument is `0`, first calls
   `func_0x3c0464b8()`) formats and emits `"\r\nSTANDBY=%d\r\n"` to the main SoC.
4. Generic `0x81` ack is returned to the peer.

The argument actually materialised into `FUN_3c0421F0` at the call site is not shown as an
operand in the decompiled handler (`FUN_3c0421F0();`), so which value appears in `%d` — the
received byte or a local standby flag — is not resolved here; the routine's own `param_1 == 0`
branch is the only explicit use of that argument. The subsequent power-down actions live on
the main SoC; nothing further is executed in `payload_1` beyond latch + print.

## Confidence & unknowns

**Confident (direct code + constant evidence):**
* Outbound frame = `80 0F 01 | state | 00×15` (19 bytes); inbound reads one byte at payload+2.
* Inbound always writes `RAM[0x20040F9D] = 1`; for state `0` or `1` it calls `FUN_3c0421F0`.
* `FUN_3c0421F0` emits `"\r\nSTANDBY=%d\r\n"` (format pointer `0x3C2F0F70`, literal
  `_DAT_3c042208` = `0x3C042208`); it calls `func_0x3c0464b8()` when its argument is `0`.
* The outbound builder does **not** print locally (no `FUN_3c041b2c` call).

**Inferred (labelled as such):**
* `0/1` = standby off/on (a state level, not an action); exact polarity unproven.
* `0x20040F9D` is a standby/activity latch inside the `0x20040Fxx` BT state block.

**Unknown / not verified:**
* Readers of `0x20040F9D` (outside the named files) and any subsequent power-down action.
* The value passed into `FUN_3c0421F0` (`%d`) at the call site.
* Bodies of `FUN_3c04a940`, `FUN_3c04196c`, `func_0x3c0464b8`.
* Poster of app event `0x19`; ack body beyond the 2-byte cmd16 echo.
