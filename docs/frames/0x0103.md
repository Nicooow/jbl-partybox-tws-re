# 0x0103 — TWS link teardown / disconnect request

BESAUD command `0x0103` is the application-layer **"tear the TWS link down"** message.
One side sends it to the peer; the peer obeys only if it is currently in the
`ctx+8 == 2` link state, in which case it stops its TWS state machine and closes the
subsystem object referenced by `ctx+0x2f0`. The frame carries **no data**: the meaning is
the command id alone, and the 16 trailing payload bytes are zero padding (ignored on
receive).

* Firmware: `extracted/payload_1.bin` (BES2000IK), Thumb, load base `0x3C000000`. File offset = VA − `0x3C000000`. The same bytes are aliased at `0x0C000000` (Δ `0x30000000`).
* Shared context struct: `ctx = 0x2002F31C` (confirmed: literals `1cf30220` at file/VA `0x3C01A508`, `0x3C01A880`, `0x3C013144`, `0x3C01AC6C`, `0x3C014154` all = `0x2002F31C`).
* Frame envelope (per repo README): `[type][cmd16 LE][payload…]`; `0x80`=command, `0x81`=ack/response.
* Evidence status: **static reverse engineering only** (not yet live-injected). Addresses below are VA unless "file 0x" is stated.

## Wire format

### Outbound — speaker → peer (builder `FUN_3c01af50`)

The builder assembles an 18-byte local buffer `[cmd16][16 × 0x00]`, then the generic
sender `FUN_3c019fe0` prefixes the transport type byte `0x80`. Total on the wire = **19 bytes**.

| offset | size | field | value / semantics |
|---|---|---|---|
| 0 | 1 | type | `0x80` — command (written by `FUN_3c019fe0`, `uRam200329e8 = 0x80`) |
| 1 | 2 | cmd16 (LE) | `03 01` = `0x0103` |
| 3 | 16 | payload | all `0x00` — fixed padding, carries no data |

### Inbound — peer → speaker (handler `parse_cmd` case @ `0x3C01A232`)

| offset | size | field | value / semantics |
|---|---|---|---|
| 0 | 1 | type | must be `0x80` (path taken when the RX dispatcher routes a *command*) |
| 1 | 2 | cmd16 (LE) | `03 01` = `0x0103` — the only field the handler reads (`*param_1`) |
| 3 | 16 | payload | ignored by the handler |

**Reply.** Like every BESAUD command, receipt triggers the generic 18-byte ack from
`FUN_3c01a08c` (type `0x81`, body = the stack buffer whose first 2 bytes echo the command
id). For `0x0103` the handler writes *only* the cmd16 echo into that buffer before sending
(the tail at `0x3C01A25C`–`0x3C01A266`), so the remaining 16 ack bytes are whatever the
buffer already held — see *Unknowns*.

## Emitted side

**Builder:** `FUN_3c01af50` (file `0x1AF50`) — 8 ULL instructions of constants:

```
uStack_1c = 0x103;  uStack_18 = 0;  uStack_14 = 0;  uStack_10 = 0;  uStack_c = 0;
FUN_3c019fe0(&uStack_1c, 0x12, 1000);   /* buf, len=18, timeout_ms=1000 */
```

Every emitted value is a compile-time constant (cmd16 immediate `0x0103`; all payload
bytes from a zeroed register `r3=0`): the frame is a pure signal, no state is sampled to
build it. Disassembly: `movw r2,#0x103; strh r2,[sp,#4]` then `str r3,[sp,#8/0xc/0x10/0x14]`.

**Trigger (internal app event `0x0A`).** The app event loop `FUN_3c012e84` (file `0x12E84`),
queued on `ctx+0x31C`, has:

```
case 10: FUN_3c01af50(); break;      /* event id 0x0A */
```

Event `0x0A` is posted **only** by `FUN_3c014158` (file `0x14158`):
`auStack_10[0]=0; uStack_c=0; FUN_3c0131d8(10, auStack_10, 8);`

Callers of `FUN_3c014158` (i.e. the situations that end up emitting `0x0103`):

1. `parse_cmd` **case `0x010D`** (`0x3C01A47E`): on inbound `0x010D`, guarded by
   `*(char*)(ctx+9) == 1`, it emits `0x0103` **unless** the local role
   (`func_0x3c01d3ac()`) is `1` or `0x10` — in those two roles it instead sets
   `ctx+0x12 = 1` and calls `FUN_3c0146f8()`.
2. `FUN_3c019cec` case 8 and `FUN_3c019834` case 8 (file `0x19CEC`/`0x19834`; profile/BT
   callback state machines). Inside `case 8`, when `*(char*)(ctx+8) != 2` and the state
   `cVar8 == 1` and `func_0x3c01d3ac() != 0x10`, it calls `FUN_3c014158()`.

**Gating for an actual transmission** is in the sender `FUN_3c019fe0`:

```
if (*(int*)(ctx + 0x310) == 0) return 0xffffffff;   /* no live TWS/SPP session ⇒ no-op */
```

So posting event `0x0A` is cheap and unconditional; the frame leaves the device only when a
real peer session handle exists at `ctx+0x310` (established during TWS bring-up — cleared
to `0` by the RX dispatcher's disconnect path, see below). `FUN_3c019fe0` also rejects
`len+1 > 0x61` (97) and, when `iRam200329e4 != 0` and `timeout_ms != 0`, sets `ctx+0x315 = 1`
and calls `FUN_3c045bcc(session, 1000)` to wait up to 1000 ms for the peer's `0x81` ack.

Side observation consistent with the role model: the local side emits `0x0103` (and never
honours an inbound `0x0103`) when `ctx+8 == 1`, i.e. the two roles are asymmetric.

## Received side

**Handler:** `parse_cmd = FUN_3c01a1f4` (file `0x1A1F4`). Dispatch is a `TBH` at `0x3C01A20A`
with base `0x3C01A20E` (`base = TBH_addr + 4`), index `cmd16 − 0x100`. Decoded entry for
`0x0103` (index 3) = `0x0012` ⇒ target `0x3C01A20E + 2*0x12 = 0x3C01A232`. Handler (0x3C01A232):

```c
case 0x103:
  if (*(char *)(ctx + 8) == 2) {            /* state gate */
    FUN_3c014114(1);                        /* → ctx+0x340 = 7 (if it was 1..3); post event 9 */
    *(undefined1 *)(ctx + 0x1b) = 0;
    FUN_3c04580c(*(undefined4 *)(ctx + 0x2f0));   /* close subsystem object at ctx+0x2f0 */
    if (func_0x3c043958() == 1 && *(char *)(ctx + 0x15) == 0)
      func_0x3c013304();                    /* post event 0x13 */
  }
  break;   /* falls to the generic 0x81 ack send */
```

`iVar8 == iRam3c01a508 == ctx == 0x2002F31C`, so every `ctx+…` offset below is literal.

**State gate — `*(u8*)(ctx+8) == 2`.** If the byte at `ctx+8` is not `2`, the case is a
complete no-op (the device still sends the standard ack, but performs no teardown). This is
the same state byte that the event loop's role-switch (case `0x0D`) writes with value `1`
or `2`, and that the profile callbacks test for `== 1` before emitting `0x0103`. Working
model (inference, not proven): `ctx+8` is the TWS link role — `1` = the side that initiates
teardown, `2` = the side that obeys an inbound teardown. Values `3`/`4` are post-teardown
states written by the event-6 handler `FUN_3c01abc8`.

**Writes performed into `ctx` (`0x2002F31C`), exactly:**

| offset | size | written value | source |
|---|---|---|---|
| `ctx+0x340` | 4 (only when previously ∈ {1,2,3}) | `7` | `FUN_3c014114(1)` |
| `ctx+0x11` | 1 | `1` | `FUN_3c014114(1)` |
| `ctx+0x1b` | 1 | `0` | handler directly |
| `ctx+0x31C` (queue) | — | posts event `9` (8-byte buffer, `[0]=1`) | `FUN_3c014114(1)` → `FUN_3c0131d8(9,…)` |
| `ctx+0x31C` (queue) | — | posts event `0x13` (no payload) | `func_0x3c013304()` → `FUN_3c0131d8(0x13,0,0)` |
| `ctx+0x2f0` target obj | 1 | obj `+4`: `2 → 1` (then `FUN_3c04539c(obj)`) | `FUN_3c04580c` / `FUN_3c045768` |

`func_0x3c043958()` is a global read: `ldr r0,[0x3C043960(=0x2002ABE0)]; bx lr` — i.e.
`return *(u32*)0x2002ABE0;` compared `== 1`. The `ctx+0x15 == 0` check is a secondary
"not already tearing down" guard.

**Related teardown path (for contrast).** `FUN_3c01a8a8` (file `0x1A8A8`) is the RX/link
event dispatcher. Its SPP-disconnect case `0x22` (`0x3C01A8A8` region) does:

```c
case 0x22:
  if (*pcRam3c01aa14 != 0) return param_1;
  if (func_0x3c018300() != 6) FUN_3c018174(7);
  FUN_3c0131d8(6, 0, 0);                 /* post event 6 = full local teardown */
  *(undefined4 *)(ctx + 0x310) = 0;      /* drop the session handle */
```

Event `6` → `FUN_3c01abc8` (file `0x1ABC8`) performs the **full** teardown: branches on
`ctx+8` (`==1` → set `ctx+8 = 3` or `4`; else `ctx+8 = 4`), calls `FUN_3c014114(1)`,
clears flags `FUN_3c04101c(4/6/3)`, closes three subsystem objects via `FUN_3c04580c`
(including `*(u32*)(ctx+0x2f0)`), copies `ctx+9 = ctx+8`, sets `ctx+0x15 = 0`, and zeroes
`ctx+0x308`.

So `0x0103` (application-layer "peer is going away") and link event `0x22` (SPP transport
dropped) are two *independent* triggers. `0x0103` runs only the partial teardown above
(state → 7, `ctx+0x1b = 0`, close `ctx+0x2f0`, optional event `0x13`); it does **not** post
event `6` and does **not** itself clear the session `ctx+0x310`. Event `6` is the heavier
path.

## Confidence & unknowns

**Confident (direct code + constant evidence):**
* Outbound frame is `80 03 01 | 00×16` (19 bytes); inbound reads only the cmd16 `0x0103`.
* Emitted from app event `0x0A`, posted solely by `FUN_3c014158`; transmission gated on a
  live session at `ctx+0x310`.
* Inbound handler is a full no-op unless `*(u8*)(ctx+8) == 2`; when taken it sets
  `ctx+0x340 = 7` (if prior 1–3), `ctx+0x11 = 1`, `ctx+0x1b = 0`, posts event `9` (payload
  `[1,…]`), closes the object at `ctx+0x2f0`, and conditionally posts event `0x13`.
* `ctx = 0x2002F31C` for every function here (literal-pool verified).

**Inferred (labelled as such):**
* `ctx+8` is the TWS link role: `1` = initiator/master side (emits `0x0103`, never obeys it),
  `2` = the side that obeys an inbound `0x0103`. The asymmetry is proven by code; the
  master/slave naming is not.
* `0x0103` is a *request/notification* to the peer to drop the shared TWS link; the local
  effect on the receiver is the partial teardown described above. (Exact direction "who is
  leaving" vs "who is being told to leave" is not distinguishable from the static code alone.)

**Unknown / not verified:**
* **Ack body for `0x0103`.** The generic tail writes only the 2-byte cmd16 echo; the other
  16 ack bytes are uninitialised stack remnants on this path. Live ack capture is needed to
  say what a peer actually observes.
* **Semantic of the payload bytes** on outbound (always zero) — whether any peer/version
  ever fills them is unknown; the local handler ignores them.
* `0x2002ABE0` (`func_0x3c043958` global) and `0x200351EC` (`func_0x3c01d3ac` role byte, read
  at `+5`) are unlabelled RAM globals; their writers were not located.
* Whether `ctx+0x2f0` object close is fatal to the link by itself, or just one step of the
  sequence, is not resolved (its `FUN_3c04539c` callee was not decompiled).
