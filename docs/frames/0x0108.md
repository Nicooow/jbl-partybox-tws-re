# 0x0108 — TWS stereo-channel assignment (committed variant)

BESAUD command `0x0108` is one of the two **"assign the TWS Left/Right channel"** messages
(the twin is `0x0110`, see `0x0110.md`). It carries a single **mode byte at payload offset 0**.
On the **emit** side it logs the channel name and commits the value to **both** `ctx+0x18`
and `ctx+0x19`. On the **receive** side it maps the wire code — *mirrored* (`3→4`, `4→3`,
anything else `→2`) — into `ctx+0x19` and logs it. Both the transmission and the channel log
are gated on a live peer session (`*(u32*)(ctx+0x310) != 0`).

* Firmware: `extracted/payload_1.bin` (BES2000IK), Thumb, load base `0x3C000000`. File offset = VA − `0x3C000000`. Aliased at `0x0C000000` (Δ `0x30000000`).
* Shared context struct: `ctx = 0x2002F31C` (literal `1cf30220` at `0x3C01A508`; also `0x3C01AE64`, `0x3C01AF0C`, `0x3C01AF4C`).
* Frame envelope: `[type][cmd16 LE][payload…]`; `0x80`=command, `0x81`=ack. Typical fixed payload 18 bytes.
* Evidence status: **static reverse engineering only** (not live-injected). Addresses are VA unless "file 0x" is stated.

## Shared helpers (verified from the image)

`FUN_3c015b18(mode)` is a **one-argument debug logger**. Its disassembly
(`0x3C015B18`) compares **r0** against 3, 4 and 2 and tail-calls `uart_printf` (`FUN_3c041b2c`):

| r0 (mode) | string | literal VA |
|---|---|---|
| `2` | `"\r\nTWSLR=S\r\n"` | `0x3C04FAB8` |
| `3` | `"\r\nTWSLR=L\r\n"` | `0x3C04FAA0` |
| `4` | `"\r\nTWSLR=R\r\n"` | `0x3C04FAAC` |
| anything else | *(return, no print)* | — |

`r1` is **never read** by this function (the "second argument" the decompiler shows at the
call sites is inert — see *Answer 4*). `ctx = 0x2002F31C` for every function below.

## Wire format

### Outbound — speaker → peer (builder `FUN_3c01ae28`, file `0x1AE28`)

The builder assembles an 18-byte local buffer; `FUN_3c019fe0` prefixes the transport type byte
`0x80`. Total on the wire = **19 bytes**.

| offset | size | field | value / semantics |
|---|---|---|---|
| 0 | 1 | type | `0x80` — command (written by `FUN_3c019fe0`) |
| 1 | 2 | cmd16 (LE) | `08 01` = `0x0108` |
| 3 | 1 | payload[0] | **mode byte** — the channel value, raw (no remap) |
| 4 | 15 | padding | all `0x00` |

### Inbound — peer → speaker (handler `parse_cmd = FUN_3c01a1f4`, case `0x0108` @ `0x3C01A3D2`)

| offset | size | field | value / semantics |
|---|---|---|---|
| 0 | 1 | type | must be `0x80` (command path) |
| 1 | 2 | cmd16 (LE) | `08 01` = `0x0108` |
| 3 | 1 | payload[0] | mode byte, read as `(char)param_1[1]` (payload byte 0) |
| 4 | 15 | padding | ignored |

**Reply.** `break` falls through to the generic 18-byte ack from `FUN_3c01a08c(buf, 0x12)`
(type `0x81`); the tail writes `(uint3)cmd16` into the buffer, so the first bytes echo
`08 01`, the rest are stack remnants (see *Unknowns*).

## Emitted side (builder `FUN_3c01ae28`)

```c
void FUN_3c01ae28(undefined4 param_1) {
  byte v = (byte)param_1;
  buf[0..1] = 0x0108;  buf[2] = v;  buf[3..17] = 0;
  func_0x3c015b18(v, 8);          /* → prints TWSLR=S/L/R ; r1 = 8 is inert */
  FUN_3c019fe0(buf, 0x12, 1000);  /* send 18 bytes, timeout 1000 ms (needs ctx+0x310 != 0) */
  *(u8*)(ctx + 0x18) = v;
  *(u8*)(ctx + 0x19) = v;
}
```

Disassembly confirms the shape exactly (`0x3C01AE28`): `movs r1,#8` → `strh.w r2,[sp,#4]`
(cmd `0x0108`) → `strb.w r0,[sp,#6]` (payload[0] = param_1) → `bl 0x3c015b18` →
`bl 0x3c019fe0` → `strb r4,[r3,#0x18]` / `strb r4,[r3,#0x19]` (`r3 = ctx = 0x2002F31C`,
`r4 = param_1`). The ctx commit happens **after** the send.

**Trigger (internal app event `0x11`).** App event loop `FUN_3c012e84` (file `0x12E84`,
two aliased copies `0x3C01…`/`0x0C01…`):

```c
case 0x11:  FUN_3c01ae28(*(undefined1 *)(puVar5 + 1));  break;   /* event id 0x11 */
```

so the emitted mode byte is **the first data byte of the queued message `0x11`**
(`(byte)msg[1]` — the value the poster stored just past the event id).

**Gating.** `FUN_3c019fe0` no-ops unless `*(u32*)(ctx+0x310) != 0` (live TWS/SPP session);
it also rejects `len+1 > 0x61` and, when armed, waits up to `timeout_ms` for the peer's `0x81`.

## Received side (case `0x0108`)

```c
case 0x108:
  if ((char)param_1[1] == 3)      *(u8*)(ctx + 0x19) = 4;
  else if ((char)param_1[1] == 4) *(u8*)(ctx + 0x19) = 3;
  else                            *(u8*)(ctx + 0x19) = 2;   /* 0,1,2 and 5…255 */
  func_0x3c015b18(*(u8*)(ctx + 0x19), 3);                    /* → prints TWSLR=…, r1=3 inert */
  break;   /* → generic 0x81 ack */
```

`iRam3c01a508 == 0x2002F31C == ctx` (literal verified), so every `ctx+…` offset is literal.

### Answer 1 — wire byte ↔ internal value ↔ channel name

| wire payload[0] | stored `ctx+0x19` | `FUN_3c015b18` prints | channel |
|---|---|---|---|
| `3` | `4` | `TWSLR=R` | Right |
| `4` | `3` | `TWSLR=L` | Left |
| `2` (and every other value) | `2` | `TWSLR=S` | Stereo / both |

The receive map is **mirrored**: wire `3`→local `4`, wire `4`→local `3`, else→`2`. Since the
emitter puts the *raw internal* value on the wire (`w = v`), a device that is internally `3`
(Left) sends `w=3`, which the peer stores as `4` (Right). The pair is therefore complementary
(local L ↔ peer R) — i.e. the sender announces its own channel and the receiver takes the
opposite. (Mirror interpretation = inference; the raw mapping is code-fact.)

### Answer 2 — provenance of the emitted value

The value is **not** sampled from `ctx`; it is passed in: app event `0x11` carries it in its
message body, and `FUN_3c012e84` forwards `(byte)msg[1]` into `FUN_3c01ae28`. The builder then
uses that one byte for three things verbatim: `payload[0]`, the log selector, and both `ctx`
commits. So the wire byte == the internal value == the logged channel (no remap on emit).

### Answer 3 — `ctx+0x18` vs `ctx+0x19`

Both hold the same ternary channel code (`2=S, 3=L, 4=R`), but they are written by different
producers:

| field | written by | role (working model) |
|---|---|---|
| `ctx+0x19` | inbound `0x0108` and `0x0110`; outbound `0x0108` and `0x0110` builders | the **active / current** TWS channel — the field the dedicated channel commands keep up to date in both directions |
| `ctx+0x18` | inbound `0x0101` (the full status push); outbound `0x0108` builder | the **configured / peer-negotiated** channel copy — set by the bulk status message, and re-committed here by a locally-initiated `0x0108`; `0x0110` never touches it |

Within `parse_cmd`/the dispatcher/the builders both fields are **write-only** (no read), so the
downstream consumer (audio routing / LED) lies outside this function set. The emitter writes
*both* slots, which is the distinguishing feature of `0x0108` versus its twin `0x0110`.

### Answer 4 — why the logger's second argument differs (`8` vs `3` vs `0xb`)

`FUN_3c015b18` **never reads r1**. The call sites nevertheless set it —
`8` (local `0x0108` builder), `3` (both inbound handlers), `0xb` (local `0x0110` builder) —
and, because the function ends in a `b.w uart_printf` **tail call without touching r1**, that
value is handed to the *variadic* `uart_printf` as its (unused) first variadic argument. The
referenced literals (`TWSLR=S/L/R`) contain no conversion specifier, so the argument is
**inert** in all three cases. It is most likely a dead/legacy parameter or a decompiler-visible
register leftover (the sibling `FUN_3c015b44` even appears with *no* argument at its call sites
while the disassembly shows r0 is set); it has **no observed effect** on the frame.

## Confidence & unknowns

**Confident (direct code + constant evidence):**
* Outbound frame is `80 08 01 | v 00×15` (19 bytes); `v` = the event-`0x11` byte, used raw.
* Inbound handler stores `map(payload[0])` into `ctx+0x19` with map `3→4, 4→3, else→2`, then logs.
* `FUN_3c015b18` is a pure logger (2/3/4 → S/L/R), and its second argument is never read.
* Emit is gated on `ctx+0x310 != 0`; receive always ack-s `0x81` with the cmd16 echo.
* `ctx+0x18` and `ctx+0x19` are distinct channel slots; the emitter writes both.

**Inferred (labelled):**
* `ctx+0x19` = active channel, `ctx+0x18` = configured/negotiated channel; the L/R "mirror" pairing between the two speakers.
* `2/3/4` = Stereo/Left/Right per the `TWSLR` log names.

**Unknown / not verified:**
* A **live injection** has not been run for `0x0108`; the mirror semantics is derived from code, not observed on a peer.
* Consumer of `ctx+0x18`/`ctx+0x19` (audio router / effect) was not located (write-only here).
* The exact meaning of the inert logger argument (`8`/`3`/`0xb`) is unresolved.
* Whether any peer fills payload bytes `1…15` — the local handler ignores them (`0x00` on emit).
