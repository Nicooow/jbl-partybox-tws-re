# 0x0111 — "PST" state set (0/1) with a conditional application notification

BESAUD command `0x0111` carries a single **"PST" flag byte** at payload offset 0. Both directions
store it at `ctx+0x307` and emit a `PST=1` / `PST=0` debug line. On **receive**, if the byte is
`0` **and** the global flag at RAM `0x20031281` is non-zero, the handler additionally calls
`FUN_3c0439ec()` (the same routine that runs for internal app event `0x13`). Unlike
`0x0108`/`0x0110`, the helper involved (`FUN_3c015b44`, the `PST` logger) is **not** the
`TWSLR` logger — it is a separate one-argument logger with its own live-session gate.

* Firmware: `extracted/payload_1.bin` (BES2000IK), Thumb, load base `0x3C000000`. File offset = VA − `0x3C000000`. Aliased at `0x0C000000` (Δ `0x30000000`).
* Shared context struct: `ctx = 0x2002F31C` (literal at `0x3C01A508`, `0x3C01AF4C`).
* Frame envelope: `[type][cmd16 LE][payload…]`; `0x80`=command, `0x81`=ack. Typical fixed payload 18 bytes.
* Evidence status: **static reverse engineering only**.

## Shared helpers (verified from the image)

`FUN_3c015b44(param)` — disassembled at `0x3C015B44`:

```
0x3C015B44  push {r4,lr}
0x3C015B46  mov  r4, r0
0x3C015B48  bl   0x3c01ac7c          ; gate = (*(u32*)(ctx+0x310) != 0)
0x3C015B4C  cbz  r0, 0x3c015b5c      ; if no live session → return (no print)
0x3C015B4E  cmp  r4, #1
0x3C015B50  beq  0x3c015b5e          ; param == 1
0x3C015B52  ldr  r0, [pc,#0x14]      ; → 0x3C04FAD0 "\r\nPST=0\r\n"
0x3C015B54  pop.w {r4,lr}; b.w 0x3c041b2c   ; uart_printf("PST=0")
0x3C015B5E  ldr  r0, [pc,#0xc]       ; → 0x3C04FAC4 "\r\nPST=1\r\n"
0x3C015B60  pop.w {r4,lr}; b.w 0x3c041b2c   ; uart_printf("PST=1")
```

* **Gate** `FUN_3c01ac7c()` (disasm `0x3C01AC7C`): `ldr r3,[pc,#0xc]` (=`0x2002F31C`); `ldr.w r0,[r3,#0x310]`; `it ne / movne r0,#1` ⇒ **`return *(u32*)(ctx+0x310) != 0`** — the *same* live-session test `FUN_3c019fe0` uses to decide whether to transmit.
* **Effect:** purely a **debug logger**. `param == 1` → `uart_printf("PST=1")`; any other value → `uart_printf("PST=0")`; nothing at all if no live session.
* `r1` is **never read** (same as `FUN_3c015b18`; see *Answer 3*). `ctx = 0x2002F31C`.

## Wire format

### Outbound — builder `FUN_3c01af10(byte param_1)` (file `0x1AF10`)

| offset | size | field | value / semantics |
|---|---|---|---|
| 0 | 1 | type | `0x80` (written by `FUN_3c019fe0`) |
| 1 | 2 | cmd16 (LE) | `11 01` = `0x0111` |
| 3 | 1 | payload[0] | **PST byte** (0 or 1 in practice; used raw) |
| 4 | 15 | padding | all `0x00` |

Total 19 bytes.

### Inbound — handler `parse_cmd` case `0x0111` @ `0x3C01A272` (and inlined copy in `FUN_3c01a8a8`)

| offset | size | field | value / semantics |
|---|---|---|---|
| 0 | 1 | type | `0x80` |
| 1 | 2 | cmd16 (LE) | `11 01` = `0x0111` |
| 3 | 1 | payload[0] | **PST byte**, read as `(char)param_1[1]` |
| 4 | 15 | padding | ignored |

**Reply.** `break` → generic `0x81` ack via `FUN_3c01a08c(buf, 0x12)` with cmd16 echo `11 01`.

## Emitted side (builder `FUN_3c01af10`)

```c
void FUN_3c01af10(byte param_1) {
  buf[3..17] = 0;
  buf[0..1] = 0x0111;  buf[2] = param_1;
  FUN_3c015b44(param_1);              /* → prints PST=1/0 (gated on live session) */
  *(u8*)(ctx + 0x307) = param_1;
  FUN_3c019fe0(buf, 0x12, 1000);      /* send 18 bytes, 1000 ms (needs ctx+0x310 != 0) */
}
```

Disassembly (`0x3C01AF10`): `mov r4,r0` (param in r4) → `mov.w r2,#0x111` → `strb.w r0,[sp,#6]`
(payload[0]) → `strh.w r2,[sp,#4]` (cmd) → `bl 0x3c015b44` → `ldr r3,[pc,…]` (=`ctx`) →
`strb.w r4,[r3,#0x307]` → `bl 0x3c019fe0`. **r0 (=param_1) is preserved from entry into the
`bl 0x3c015b44`**, i.e. the real call is `FUN_3c015b44(param_1)` even though Ghidra prints
`FUN_3c015b44()` with no argument (its prototype for that function is guessed as 0-arg).

**Trigger (internal app event `0x1B`).** Event loop `FUN_3c012e84`:

```c
case 0x1b:  FUN_3c01af10(*(undefined1 *)(puVar5 + 1));  break;   /* event id 0x1B */
```

The emitted PST byte is the first data byte of queued message `0x1B`.

## Received side (case `0x0111`)

```c
case 0x111:
  uVar4 = param_1[1];                       /* payload[0], the PST byte */
  *(char *)(ctx + 0x307) = (char)uVar4;     /* store raw */
  FUN_3c015b44((char)uVar4);                /* → prints PST=1/0 (gated) */
  if ((*(char *)(ctx + 0x307) == 0) && (*pcRam3c01a50c != 0))
      FUN_3c0439ec();                       /* extra notification when PST==0 and flag set */
  break;   /* → generic 0x81 ack */
```

`pcRam3c01a50c` is the literal at `0x3C01A50C`, verified to hold **`0x20031281`** (read from the
image), so `*pcRam3c01a50c` = `*(u8*)0x20031281`.

### Complete payload map

| direction | payload[0] | `ctx+0x307` | log | side effect |
|---|---|---|---|---|
| emit | `param_1` (0/1) | `= param_1` | `PST=1` if `param_1==1`, else `PST=0` | none beyond the send |
| receive | wire byte `b` | `= b` | `PST=1` if `b==1`, else `PST=0` | if `b==0 && *(u8*)0x20031281 != 0` → `FUN_3c0439ec()` |

Bytes `1…15` are ignored on receive / zero on emit.

## Answers to the frame questions

### Answer 1 — what `ctx+0x307` and RAM `0x20031281` gate

* **`ctx+0x307`** is the stored **PST flag** (a one-byte state mirrored from the frame). It is
  written by both the emit builder and the receive handler. On receive it is the immediate
  condition that decides whether the extra notification runs: **PST == 0** (i.e. "PST off").
* **RAM `0x20031281`** (byte) is a **global enable/arm flag** read through the pointer literal at
  `0x3C01A50C`. When it is non-zero the `PST==0` transition is allowed to fire `FUN_3c0439ec()`.
  Its writer was **not located** in this function set (it is an external gate, most plausibly
  "TWS/party-link active" or "remote control enabled"). The `&&` means: *notify only if the
  feature is armed **and** PST has just gone to 0.*

### Answer 2 — what `FUN_3c015b44` does

It is the **`PST` debug logger** (see disassembly above): `if (live session) uart_printf(param==1 ? "PST=1" : "PST=0")`. It performs **no state change** — the state change is the `ctx+0x307` store that the callers do themselves. Its only side condition is the live-session gate `ctx+0x310 != 0`.

### Answer 3 — why the dispatcher copy passes a length argument but `parse_cmd` does not

`FUN_3c015b44` reads **only r0**; its body never touches r1. Because it ends in a
`b.w uart_printf` **tail call** without clearing r1, whatever the caller left in r1 is handed to
the *variadic* `uart_printf` as an unused argument. The two copies of the same source simply
disagree about r1 at the call site:

| copy | call | r1 |
|---|---|---|
| `parse_cmd` (`FUN_3c01a1f4`), case `0x111` | `FUN_3c015b44((char)uVar4)` | whatever was live (not the length) |
| RX dispatcher (`FUN_3c01a8a8`, inlined), case `0x111` | `FUN_3c015b44(cVar4, sVar5 - 1)` | the received frame length minus 1 (`sVar5 = param_2[10]`) |
| emit builder (`FUN_3c01af10`) | `FUN_3c015b44(param_1)` (r0 = param) | not set (Ghidra shows no arg) |

Since the format strings (`PST=1` / `PST=0`) contain no conversion specifier, r1 is **inert** in
every copy; the difference is a register-allocation artifact of the two inlinings, **not** a
semantic difference. (It does not make the dispatcher copy behave differently.)

### Answer 4 — `FUN_3c0439ec` (the PST==0 notification)

`FUN_3c0439ec()` (file `0x439EC`):

```c
iVar1 = func_0x3c01581c();            /* get an object/handle */
obj[0x3b2] = 2;
msg = { 1, func_0x3c014108(), 2, 1, func_0x3c01cadc(),
        func_0x3c04a550(), *(u32*)0x…3A38, *(u32*)0x…3A3C, 0 };
FUN_3c013254(&msg);                   /* queue/post the application message */
```

It is the **same routine the app event loop runs for event `0x13`** (`FUN_3c012e84`, `case 0x13`
→ `FUN_3c0439ec`), and it is also reached from the `0x0103` teardown path (via
`func_0x3c013304` → event `0x13`). So an inbound `0x0111` with **PST=0 while the flag is armed**
triggers that application-side notification immediately, *in addition to* the ack — it is not
only a log line.

## Confidence & unknowns

**Confident (direct code + constant evidence):**
* Frame is `80 11 01 | pst 00×15` (19 bytes); `pst` used raw, stored at `ctx+0x307`.
* Both directions call `FUN_3c015b44` (a pure `PST=1`/`PST=0` logger gated by `ctx+0x310 != 0`).
* Inbound: `pst==0 && *(u8*)0x20031281 != 0` ⇒ `FUN_3c0439ec()`.
* `FUN_3c015b44` reads only r0; the dispatcher's extra `sVar5-1` argument is inert.
* `0x20031281` is a real global reference (`*pcRam3c01a50c`, literal verified).

**Inferred (labelled):**
* "PST" = a single boolean state (name from the log string; expansion unknown — not "TWSLR").
* `FUN_3c0439ec` is the shared "application notification" action also used by event `0x13`.

**Unknown / not verified:**
* The full name/expansion of **PST** and the semantic of `ctx+0x307` downstream.
* Who writes RAM `0x20031281`, and what it truly arms — writer not located.
* Not live-injected: the PST==0 → `FUN_3c0439ec` path and the ack behaviour are code-derived only.
* Payload bytes `1…15` unused locally; peer behaviour unknown.
